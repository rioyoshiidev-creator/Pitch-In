# PitchIn - 要件定義

最終更新: 2026-04-30

## アプリ概要

海外で活躍する日本人サッカー選手を応援するためのアプリ。
チームではなく「特定の選手」を追いかけたいファン向け。
選手が試合に出場したタイミングでアラームで知らせる機能が最大の特徴。

---

## ターゲットユーザー

- 海外リーグでプレーする日本人選手の推しがいるサッカーファン
- 時差のある深夜・早朝の試合を見逃したくない人
- チーム単位ではなく選手単位で試合を追いたい人

- [x] どのチームの選手かを明示（ホーム・アウェイ別に表示）
- [x] スタメン / ベンチ / ベンチ外の表示
- [x] 得点・アシストの表示（分数付き）
- [x] 出場時間（何分から何分）の表示
- [x] 日付ごとのセクション表示（スティッキーヘッダー）
- [x] フォロー中の選手はスター★アイコンで区別
- [ ] 試合詳細画面（v2）

### 2. 選手情報

- [x] DBに登録された日本人選手の一覧・検索
- [x] 選手のフォロー / フォロー解除（検索結果に両方表示）
- [ ] 選手詳細画面（v2）
  - [ ] 基本情報（所属チーム・ポジション・背番号）
  - [ ] 今シーズン成績（出場数・得点・アシスト・出場時間）

### 3. フォロー機能

- [x] 選手をフォロー / フォロー解除
- [x] フォロー中の選手の試合のみ試合一覧に表示（切替可）
- [x] フォロー選手一覧の管理
- [x] フォロー中の選手が先頭に表示（試合カード内の選手ソート）

### 4. 通知機能（動作確認済み）

- [x] フォロー選手がスタメン発表されたときにPush通知
- [x] フォロー選手が控えに入ったときにPush通知
- [x] フォロー選手が招集外のときにPush通知
- [x] フォロー選手が途中出場したときにPush通知
- [x] フォロー選手が得点したときにPush通知
- [x] フォロー選手がアシストしたときにPush通知
- [x] 二重通知防止（notification_log テーブルで管理）

### 5. アラーム機能（動作確認済み・最大の差別化機能）

- [x] 試合一覧からアラームを設定できる（モーダル）
- [x] iOS：expo-alarm-kit（集中モードを突破、iOS 26以降）
- [x] アラーム設定モーダルで発火タイミングを設定可能
  - スタメン発表時 / 試合開始時 / 5分前 / 10分前 / 15分前 / 30分前 / 45分前 / 60分前
  - デフォルト: 30分前（設定画面で変更可）
- [x] 途中出場時アラームのON/OFFトグル（控えの場合、途中出場のタイミングで発火）
- [x] 同じ試合に複数フォロー選手がいる場合、アラーム対象選手を選択可能
- [x] アラームが鳴ったらアプリを開いた際に自動削除
- [x] 試合開始24時間以内の試合のみアラーム設定可能
- [x] 試合中（LIVE）でも途中出場アラームを設定可能
- [ ] Android 対応（v1.5）

**アラームフロー（スタメン時）**
```
ユーザーが試合一覧でアラームを設定
  └─ alarms テーブルに保存（alarm_timing / minutes_before / selected_player_ids）
       ↓
サーバーがスタメン発表を検知（キックオフ1時間前から1分毎ポーリング）
  └─ match_players を starter / bench / not_selected に更新
       └─ 選択選手にスタメンがいるアラームに対してサイレントプッシュを送信
            └─ fireAt = alarm_timing が 'lineup' なら即時 / 'before_kickoff' ならキックオフ - N分
                 ↓
iOSがBackgroundTaskを起動
  └─ AlarmKit に fireAt 時刻のアラームを登録
       └─ 指定時刻に🔔アラームが発火
            ↓
アプリをフォアグラウンドに戻すとアラームが自動削除
```

**アラームフロー（途中出場時）**
```
サーバーが交代イベントを検知（試合中30秒毎ポーリング）
  └─ notify_substitution=true かつ sub_alarm_fired=false のアラームを対象
       └─ 選択選手が途中出場した場合にサイレントプッシュを送信
            └─ BackgroundTask → AlarmKit に即時アラームを登録
                 └─ 🔔 アラームが発火
                      └─ sub_alarm_fired=true にセット（二重発火防止）
```

### ① 試合一覧画面（タブ1）

**フォロー切り替え**
- `フォロー中` タブ：登録選手の試合のみ表示
- `全選手` タブ：日本人選手全員の試合日程・結果

**ステータスタブ**
- `試合開始前`（デフォルト）：今後2週間
- `試合中`：現在進行中の試合（フォロー中の試合中件数をバッジ表示）
- `試合終了`：直近1週間

**表示ルール（ソート順）**
- 日付ごとにセクション分け（スティッキーヘッダー）
- セクション内: リーグ順 → 試合時刻順
- 選手: スタメン→控え→控え外の順、各グループ内でフォロー選手が先頭

**試合カード表示内容**
- 試合時刻・ライブ経過時間
- ホーム vs アウェイ（チームロゴ・スコアまたはvs）
- 日本人選手（ホーム・アウェイ別2カラム）
  - フォロー選手: ★アイコン（状態に応じた色）
  - 非フォロー選手: ●ドット
  - スタメン / ベンチ / ベンチ外ラベル
  - 出場時間（例: 65'〜）
  - ゴール・アシスト分数
- アラームボタン（フォロー選手がいる予定試合 / 試合中のみ表示）
  - 試合開始24時間以前は「○/○ ○○:○○ からアラームを設定できます」表示

---

### ② 選手画面（タブ2）

**フォロー中タブ**
- フォロー中の選手カード一覧（名前・所属チーム・リーグ）
- 各選手の通知設定（スタメン発表 / 途中出場 / 得点 / アシスト）

**選手を追加タブ（検索）**
- 検索バー（名前で絞り込み）
- 全登録選手を一覧表示
- フォロー中の選手は「✓フォロー中」ボタン（タップでフォロー解除）

### ③ 設定画面（タブ3）

- プレリリース版バナー
- **通知・アラーム**
  - デフォルトのアラームタイミング（選択モーダル）
  - 通知・アラーム設定を開く（iOS設定アプリへ）
- **ヘルプ**
  - 使い方を見る（オンボーディングを再表示）
  - アラームが鳴らない時（トラブルシューティング）
- **その他**
  - 利用規約 / プライバシーポリシー / お問い合わせ

---

### 初回オンボーディング（初回起動時のみ）

5ステップ構成。ステップ1〜3はスキップ可（スキップするとステップ4へ）。

```
ステップ1: 選手をフォローする（スクリーンショット）
ステップ2: 試合をチェックする（スクリーンショット）
ステップ3: アラームをセットする（スクリーンショット）
  └─ 「下記が原因でアラームが鳴らなくなります」注意事項を表示
ステップ4: 通知を許可する → Notifications.requestPermissionsAsync()
ステップ5: アラームを許可する → AlarmKit.requestAuthorization()
  └─ 完了後に選手追加タブへ遷移
```

---

### アラームが鳴らない時（ヘルプ画面）

設定画面からアクセス可能。

1. アプリの強制終了（タスクキル）
2. バックグラウンドApp更新がオフ（設定 → 一般 → バックグラウンドApp更新）
3. アラームの許可がオフ（設定 → Pitch-In → アラーム）
4. iOS 26未満
5. 通信環境の問題

## バックエンド処理

### データ管理フロー

```
① 管理者画面でリーグを手動登録（id・name）
    ↓
② 管理者画面からバッチ起動：チーム取得
   leagues → GET /teams?league&season → teams テーブルへ保存
    ↓
③ 管理者画面からバッチ起動：スカッド取得・選手紐付け
   全チーム → GET /players/squads?team
   → スカッド内の api_player_id が players テーブルに存在したら一致
   → チームと選手を紐付け（api_team_id を更新）+ has_japanese=true をチームに付与
   ※ position・number もこのタイミングで自動補完
   ※ 移籍検知時: 旧チームの未確定試合から match_players を削除 → 新チームに追加
    ↓
④ 自動バッチ（毎日）：試合スケジュール取得
   has_japanese=true のチームのみ → GET /fixtures?team → matches テーブルへ
    ↓
⑤ 自動バッチ（試合前1時間〜1分毎）：スタメン取得 → Push通知 → アラーム発火
⑥ 自動バッチ（試合中30秒毎）：得点・交代イベント取得 → Push通知 / 途中出場アラーム発火
```

### 手動バッチ実行タイミング

| バッチ               | 実行タイミング                     |
| -------------------- | ---------------------------------- |
| チーム取得           | シーズン開始時（年1〜2回）         |
| スカッド取得・選手紐付け | シーズン開始時 + 移籍期間（日1回） |

### 自動バッチ

| 処理               | 頻度                     | 内容                                             |
| ------------------ | ------------------------ | ------------------------------------------------ |
| 試合スケジュール取得 | 毎日1回                  | has_japaneseチームの今後2週間の試合を取得        |
| スタメン取得       | 試合開始1時間前から1分毎 | スタメン発表を検知してPush通知・アラーム発火      |
| 試合中イベント取得 | 試合中30秒毎             | 得点・アシスト・交代を検知してPush通知・アラーム発火 |

### Push通知フロー

```
API-Football（定期ポーリング）
  ↓ イベント検知
Supabase（フォローユーザー照合・notification_log で重複チェック）
  ↓ 対象デバイスのPush Token取得
Expo Push API
  ↓
APNs（iOS）
  ↓
ユーザーのデバイス
```

### アラームフロー（サイレントプッシュ経由）

```
サーバーが選手出場を検知
  ↓
Silent Push 送信（fireAt・eventType・playerName を含む）
  ↓
iOSがBackgroundTaskをバックグラウンドで起動
  ↓
AlarmService.scheduleAlarm(delaySeconds) で AlarmKit にアラームを登録
  ↓
🔔 アラームが発火（集中モード中でも鳴る）
  ↓
アプリをフォアグラウンドに戻す → AsyncStorage 経由でアラームを自動削除
```

**動作条件**
- バックグラウンドApp更新がON
- ユーザーがアプリをタスクキルしていない
- ネットワーク接続あり

## 管理者画面

ローカルで動作するWeb管理ツール（Next.js）。本番DBに直接接続。

### 画面構成

```
管理者画面
  ├─ /         ダッシュボード（選手数・試合数・アラーム数）
  ├─ /leagues  リーグ管理
  ├─ /players  選手管理
  ├─ /teams    チーム一覧（参照のみ）
  ├─ /matches  試合一覧（参照のみ）
  └─ /batches  バッチ実行
```

### 各画面の機能

#### リーグ管理（/leagues）
- 登録済みリーグ一覧（id・name・season・並び順）
- リーグ追加フォーム（API-Football の league.id・リーグ名）
- リーグ削除（関連するチーム・試合・選手紐付けをカスケード削除）
- 並び順変更（↑↓ボタン）

#### 選手管理（/players）
- 登録済み選手一覧（name・api_player_id・所属チーム・position・number）
- 選手追加フォーム（選手名・api_player_id）
- 選手削除

#### チーム一覧（/teams）
- 登録済みチーム一覧（name・リーグ・has_japanese）
- 参照のみ

#### 試合一覧（/matches）
- 参照のみ

#### バッチ実行（/batches）
- **チーム取得**: 登録リーグのチームをAPIから取得してDBへ保存
- **スカッド取得・選手紐付け**: 全チームのスカッドを取得し、登録済み選手と突合
- 各バッチの実行ログをリアルタイム表示

| テーブル           | 内容                                   | 更新方法         |

## 認証方針

- ユーザー登録不要
- 初回起動時にデバイスUUIDを自動発行・AsyncStorageに保存
- Push TokenとデバイスUUIDをサーバーに登録して管理
- 機種変更・再インストール時は設定がリセット（v1仕様）
- v1.5以降でApple/Googleログインによる設定復元を追加予定

---

## エラー・障害時の動作方針

| シナリオ | 対応 |
|---|---|
| API取得失敗 | 3回リトライ → 失敗時はスキップ |
| Silent Push 未着 | Push通知でバックアップ（アラームが鳴らなかった場合の保険） |
| 試合中断・中止 | 現状は対応なし（v1.5予定） |
| アプリ再起動時のアラーム消失 | 起動時にサーバーからアラームを自動復元 |
